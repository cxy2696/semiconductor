# 手法：因子・スコア・境界

バージョン 3.0.0 · 発効 2026-11-11 · サイト内ページ `/methodology.html` に対応

本ドキュメントは、サイト上のすべての数値の計算方法を定義します。手法を変更する場合は、本ドキュメント、サイトの手法ページ、`CHANGELOG.md`、バージョン番号を同時に更新する必要があります。

---

## 1. 研究の問い

手法が答えるのは次の 3 つだけです。

1. **この工程はいまどんな状態にあるのか。**（市場状態の読み取り）
2. **どの企業から読むべきか。**（研究優先度）
3. **自分の判断の根拠となるデータは揃っているのか。**（データ充足度）

答えないのは、将来リターン、目標株価、売買のタイミング、ポジションサイズです。

## 2. サンプルと分類

- **サンプル**：`data/universe.csv` にある 175 社の上場企業。
- **1 社 1 上場**：主上場を優先し、同じ企業を複数の市場で数えません（例：SMIC は A 株の 688981 のみ、華虹は香港上場の 1347 のみ）。
- **工程**：主な収益源によって 8 工程のいずれかに割り当てます。これは編集上の判断であり、プルリクエストで根拠を示す必要があります。
- **ロール**：fabless / foundry / idm / memory / equipment / materials / osat / module / eda_ip。
- **国**：本社地域で、13 のいずれか。**市場**：上場市場で、7 つのいずれか。両者は異なることがあります（例：NXP はオランダに本社を置き、米国に上場）。
- **製品タグ**：`taxonomy.json` にある 70 タグの統制語彙から選び、フィルタと企業ページの表示に使います。
- **企業メタデータ**：`founded`（年）と `fiscal_year_end`（月）は説明的なフィールドで、どの因子にも使いません。

企業の追加・削除は、上場していること、売上の大半が半導体であること、信頼できる株価ソースがあること、欠けている工程や地域を埋めるか主要なリーダーであることを条件とします。変更は `CHANGELOG.md` に記録します。

## 3. データフィールド

| フィールド | 定義 | 単位 | 欠損時の扱い |
| --- | --- | --- | --- |
| `price` | 最新の入手可能な終値（遅延株価） | 現地通貨 | `—` を表示し、価格系の因子から除外 |
| `change_pct` | 直近営業日の騰落率 | % | 同上 |
| `ret_30d` | 直近 30 **営業日**の騰落率 | % | 同上 |
| `ret_ytd` | 年初来の騰落率 | % | スコアには使わない |
| `market_cap` | 時価総額（現地通貨） | 現地通貨 | 規模因子から除外 |
| `market_cap_usd` | 時価総額 × 為替レート | USD | 規模因子から除外 |
| `pe` | 静的 PER（直近年度の EPS） | 倍 | ≤ 0 または欠損 → バリュエーション因子が欠損 |
| `pb` | PBR | 倍 | 欠損しても他の因子には影響しない |
| `roe` | ROE | % | 欠損 → 品質因子が欠損 |
| `turnover` | 売買回転率 | % | 表示のみ。スコアには使わない |
| `high_52w` / `low_52w` | 直近 250 営業日の最高値 / 最安値 | 現地通貨 | 欠損 → レンジ内の位置が欠損 |
| `coverage` | 8 項目のうち揃っている割合 | 0–1 | §6 を参照 |

> 52 週レンジは 250 営業日で近似しており、必ずしも暦年と一致しません。

## 4. 因子の定義

すべての因子はまず**その工程の中**で 0〜100 のパーセンタイルに正規化します。企業数が 8 社未満の工程は全サンプルにフォールバックします。パーセンタイルは中位順位（同値は平均順位）を用います。

### 4.1 品質

```text
quality = percentile_rank(ROE, peer_group)
```

ROE が高いほど品質スコアは高くなります。ROE が欠けている場合は因子も欠損です。

### 4.2 バリュエーション

```text
valuation = percentile_rank(-PE, peers_with_positive_PE)   # PE > 0
valuation = missing                                        # PE ≤ 0 or missing
```

PER が低いほどバリュエーションスコアは高くなります。赤字企業に「割安」という錯覚を与えることはせず、バリュエーション因子を単に欠損とします。

### 4.3 モメンタム

```text
momentum = 0.6 × percentile_rank(ret_30d, peers)
         + 0.4 × percentile_rank(range_position, peers)

range_position = (price - low_52w) / (high_52w - low_52w)  ∈ [0,1]
```

一方の成分が欠けている場合は残りのウエイトで再正規化し、両方が欠けている場合は因子も欠損とします。

### 4.4 規模

```text
size = percentile_rank(log10(market_cap_usd), peers)
```

規模は流動性と耐性の代理指標であり、品質の尺度ではありません。

### 4.5 研究優先度

```text
priority = 100 × Σ(w_i × factor_i) / Σ(w_i)      # sum over available factors only
w = {quality: 0.30, valuation: 0.25, momentum: 0.25, size: 0.20}
```

- 欠損した因子を 50 で埋めることはせず、残りのウエイトを**再正規化**します。中立値によって生じる歪みを避けるためです。
- `factor_coverage = Σ available weights / 1.0` は、そのスコアがどれだけ信頼できるかの目安として使います。
- 結果は整数に丸め、0〜100 に収めます。

## 5. リスクフラグ

| フラグ | 発動条件 | 意味 |
| --- | --- | --- |
| `loss` | `pe ≤ 0` | 直近年度が赤字。バリュエーションは適用外 |
| `rich` | バリュエーションスコア ≥ 80 | 同一工程の中で割高 |
| `small` | 時価総額 < 20 億 USD | 規模と流動性が弱い |
| `sharp` | `abs(ret_30d)` ≥ 25% | 直近 30 日で大きな値動き |
| `stale` | スナップショットが 48 時間より古い | データが古い可能性がある |

`risk_level`：有効なフラグがなければ低、1〜2 個で中、3 個以上で高。`stale` は別途表示し、リスクレベルには数えません。

## 6. データ充足度

8 項目は `price`、`change_1d`、`ret_30d`、`market_cap_usd`、`pe`、`pb`、`roe`、`range` です。

```text
coverage = available fields / 8
≥ 0.875 → high      (7–8 fields)
≥ 0.625 → medium    (5–6 fields)
< 0.625 → low       (4 or fewer fields)
```

充足度はフィールドが**存在するか**を測るもので、データが正確かどうかを測るものではありません。

## 7. 市場状態

`ret_30d` を持つすべての企業について：

```text
breadth    = advancing companies / valid companies
median     = median(ret_30d)
dispersion = P75(ret_30d) - P25(ret_30d)
```

分類：

| 条件 | 状態 |
| --- | --- |
| breadth ≥ 0.60 かつ median > 2% | 拡大 |
| breadth ≤ 0.40 かつ median < −2% | 収縮 |
| それ以外 | 中立 |

先行工程 / 遅行工程は、企業数が 3 社以上ある工程のうち騰落中央値が最も高い / 低い工程です。市場状態は現在の構造を記述するものであり、方向を予測するものではありません。

## 8. リサーチスクリーン

| スクリーン | ルール | 並び順 |
| --- | --- | --- |
| 品質優先 | `quality ≥ 70` かつ `valuation ≥ 50` | 研究優先度の降順 |
| バリュエーション調整 | `valuation ≥ 70` かつ `quality ≥ 50` | バリュエーションの降順 |
| モメンタム先行 | `momentum ≥ 80` かつ `ret_30d > 0` | モメンタムの降順 |

各スクリーンは最大 8 社で、株価がある企業のみを含みます。

## 9. 読み方

- **スコアは相対値**：同じ企業でも、別の工程や別の日付ではスコアが変わります。
- **スコアが高い＝良い企業ではない**：単に割安である、モメンタムに乗っている、小さな工程に分類されているだけかもしれません。
- **スコアが低い＝悪い企業ではない**：サイクルの底にある、データが欠けている、割高だが品質は高い、といった可能性があります。
- **工程をまたいでスコアを比較しない**：正規化は工程の中で行います。
- **充足度とあわせて読む**：充足度の低いスコアは参考程度に扱ってください。

## 10. 既知の限界

1. 株価は遅延値または終値で、注文板や日中のシグナルは含みません。
2. 静的 PER は高成長企業に不利で、赤字企業にはバリュエーション因子がありません。
3. 増収率、受注、稼働率、在庫のデータがないため、品質因子は ROE のみに依存しています。
4. 52 週レンジは 250 営業日で近似しています。
5. 為替レートは日次で更新されるため、通貨をまたぐ比較には日次の誤差が伴います。
6. 分類には編集上の判断が含まれ、事業の変化に応じて四半期ごとの見直しが必要です。
7. サンプルは大規模な上場企業に偏っているため、生存者バイアスを含みます。

## 11. 変更管理

1. 計算式や閾値を変更する → 本ドキュメント + サイトの手法ページ + `CHANGELOG.md` を更新し、メジャーバージョンを上げる。
2. 因子を追加する → まずオフラインで比較し、スクリーンへの影響を記録してからマージする。
3. サンプルや分類を変更する → 対象企業、理由、影響するページをプルリクエストに列挙する。
4. ビルドのたびにスコアを再計算し、過去のスコアは保持しません。バックテストには `data/snapshots/` の履歴スナップショットを使ってください。
