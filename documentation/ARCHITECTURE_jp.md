# アーキテクチャ

バージョン 3.0 · 2026-11-11

## 1. システムコンテキスト

```text
┌────────────────────┐        ┌──────────────────────────┐
│ Eastmoney quotes   │        │ open.er-api.com FX       │
└─────────┬──────────┘        └────────────┬─────────────┘
          │                                │
┌─────────▼──────────┐        ┌────────────▼─────────────┐
│ Whitelisted RSS    │        │ data/symbols.json mapping│
└─────────┬──────────┘        └────────────┬─────────────┘
          └──────────────┬─────────────────┘
                         ▼
              semcore fetch (may fail; never blocks the build)
                         ▼
        data/snapshots/latest.json (single input, committed)
                         ▼
   semcore analytics → semcore build (Jinja2 + SVG)
                         ▼
      docs/ (HTML / CSS / JS / JSON / sitemap)
                         ▼
              GitHub Pages (static hosting)
```

設計上の制約：

- **サーバーなし、データベースなし**：サイトは純粋に静的な成果物です。
- **データはビルド時に取得**：ブラウザがサードパーティ API を呼ぶことはなく、CORS・レート制限・プライバシーの問題を避けています。
- **劣化運転が可能**：取得に失敗した場合は前回のスナップショットを使い、ページにデータ時点と stale マーカーを表示します。
- **単一の真実の源**：企業マスタデータ、分類、インターフェース文言、コンテンツは、それぞれ 1 か所にだけ存在します。

## 3. ビルドパイプライン

1. **設定の読み込み**：`config.py` がパス、4 つのロケール、サイト URL を解決します。
2. **マスタデータの読み込み**：`universe.load_universe()` が CSV を読み、`taxonomy` に照らして列挙値、一意性、Web サイトの形式を検証します。
3. **スナップショットの読み込み**：`market.load_snapshot()` が `latest.json` を読みます。存在しない場合、ビルドは失敗し、先に `fetch` を実行するよう促します。
4. **分析の計算**：`Analytics.build()` が企業・株価・為替をマージし、因子、スコア、リスクフラグ、工程統計、市場状態、リサーチスクリーンを計算します。
5. **コンテンツの読み込み**：`content.load_all_knowledge()` が各ロケールのフロントマターと Markdown を解析し、`load_glossary()` が用語を読み込みます。
6. **ページのレンダリング**：4 つのロケールそれぞれについて、固定 7 ページ + ナレッジ 12 ページ + 企業 175 ページをレンダリングし、アセットをコピーします。
7. **補助ファイルの書き出し**：`sitemap.xml`、`robots.txt`、`.nojekyll`、`latest_data.json`、`api/snapshot.{en,zh,ja,de}.json`、旧ルートのリダイレクト、`/en/` のリダイレクトスタブ、`404.html`。
8. **検証**：`validate_artifacts()` が必要なファイル、JSON 契約、旧フィールド、CDN が含まれていないことを確認します。

## 4. モジュール境界

### sources/eastmoney.py

- `resolve_secid()`：市場のルールに従って候補の `secid` を組み立て、各コードの一致を検証して結果をキャッシュに書き込みます。
- `fetch_quote()` / `fetch_history()`：リトライと 15 秒のタイムアウト付きの HTTP リクエスト。
- `build_market_entry()`：生のフィールドをスナップショットのエントリ（株価、騰落、時価総額、PER / PBR / ROE、52 週レンジ、30 日リターン、30 日 OHLC）に正規化します。
- 失敗時は `None` を返し、フォールバックは `market.py` が判断します。

### sources/news.py

- `fetch_feed()` はフィードを並行して取得し、1 つのフィードの失敗が他に影響しないようにします。
- `parse_feed()` は RSS 2.0 と Atom の両方に対応します。
- `_relevant()` はキーワードで絞り込み、重複を除き、先頭 24 件を保持します。

### market.py

- スレッドプール（デフォルト 6）で 175 社を取得します。
- 失敗時は前回のスナップショットのエントリを優先し、`status="stale"` を付けます。
- 為替とニュースをマージし、`latest.json` と日付付きスナップショットを書き出して、直近 30 件を保持します。

### analytics.py

- 純粋な計算のみで I/O はなく、テストが容易です。
- `Row` はテンプレートと JSON が使う中間表現です。
- パーセンタイルは工程ごとにグループ化し、企業数が 8 社未満のグループは全サンプルにフォールバックします。
- `Analytics` は工程統計、国・市場の統計、市場状態、スクリーン、モメンタムの両端を集約します。

### build.py

- `SiteBuilder` がビューの辞書（ロケールごとのローカライズ済みビュー）、URL の計算、ページコンテキスト、テンプレートのレンダリング、出力の書き出しを担います。
- すべてのページコンテキストは `t`（文言）、`href()`、`alternates`、`analytics`、`tax`、`snapshot` を含みます。
- `_legacy_payload()` は iOS 互換のための `latest_data.json` を生成します。
- `_localized_payload()` は 4 ロケール向けの `api/snapshot.{lang}.json` を生成します。

### validate.py

- `validate_data()`：マスタデータ、i18n、ナレッジ、用語集。
- `validate_artifacts()`：ページ、JSON、サイトマップ、CDN のチェック、hreflang。
- CI はビルドの前にデータチェックを、ビルドの後に全チェックを実行します。

## 5. 4 言語アーキテクチャ

| レイヤー | 仕組み |
| --- | --- |
| URL | 英語はルート、中国語は `/zh/`、日本語は `/ja/`、ドイツ語は `/de/`。すべてのページが絶対 URL の alternates を持ちます |
| 旧 URL | `/en/...` のリダイレクトスタブが対応するルートページを指します |
| インターフェース文言 | `data/i18n/{en,zh,ja,de}.json`。キーは完全に揃っており CI で検証されます |
| データラベル | `taxonomy.json` の `label` オブジェクト（`{zh, en, ja, de}` の値） |
| 長編コンテンツ | フラットファイル `content/knowledge/<slug>_<suffix>.md`。slug は言語間で同一です |
| 用語集 | 4 言語のフィールドを持つ単一ファイル。ページはアクティブな言語をレンダリングします |
| 数値 | 桁区切りと小数桁を統一。通貨のサフィックスは ISO コードを保ちます |
| 日付 | サイトは Asia/Shanghai（UTC+8）を使用。データの日付は出典に従います |

**ブラウザ内で言語を切り替えないのはなぜか？** URL を分けたほうが共有、SEO、キャッシュ、JS なし環境に有利であり、言語切り替えはビルド時に生成されるため実行時の辞書に依存しません。コストはページ数が 4 倍になることですが、静的ホスティングなら難なく吸収できます。

## 6. リンクモデル

- `SiteBuilder._page_path(locale, key, slug)` が唯一のパス生成関数です。
- テンプレートは `href('company', id)` のような関数を通してのみリンクを取得し、相対パスのハードコードを避けます。
- `rel_href()` は現在のページから対象ページへの相対パスを計算するため、`file://` で直接開いた場合も動作します。
- アセットは `root + 'assets/...'` を使い、`root` はページの深さから導出します。

## 7. レンダリングとパフォーマンス

- **サードパーティ製アセットはゼロ**：Tailwind も Plotly もフォント CDN も使いません。
- グラフは Python で SVG として生成します。散布図、スパークライン、52 週レンジバーです。
- CSS は約 30 KB、JS は約 8 KB（非圧縮）。ほとんどのページは HTML で 30〜120 KB で、企業インデックスは 175 行をサーバーサイドでレンダリングするため大きくなります。
- 企業テーブルはサーバーサイドでレンダリングし、フィルタとソートはネイティブ JS で行います。仮想リストは使いません。
- ファーストビューより上にブロッキングスクリプトは置かず、`<head>` 内の小さなインラインテーマスクリプトでテーマのちらつきを防ぎます。

## 8. アクセシビリティと SEO

- セマンティックな `header/nav/main/footer`、`aria-current`、`aria-sort`、スキップリンク。
- テーブルは `thead` を持ち、ソート可能な見出しはキーボードで操作できます。
- グラフには `role="img"`、`aria-label`、`<title>` を付けます。
- `prefers-reduced-motion` でアニメーションを無効化し、コントラストは AA を満たします。
- すべてのページが canonical URL、`hreflang` alternates、OG タグを持ち、ナレッジページは Article JSON-LD を持ち、サイトマップは全ページを網羅します。

## 11. 既知の技術的負債

1. 株価ソースが 1 つ（Eastmoney）しかなく、クロスチェック用の第 2 ソースがありません。
2. 欧州の `secid` はシードマッピングに依存しているため、新規上場では手動の調査が必要になることがあります。
3. 因子はビルドのたびにキャッシュなしで全件再計算します。175 社では性能上の問題にはなりません。
4. ニュースのキーワードリストが英語でハードコードされているため、中国語・日本語・ドイツ語メディアのカバレッジは限定的です。
5. 企業ページは構造化データ `Corporation` を出力しておらず、SEO は記事に依存したままです。
