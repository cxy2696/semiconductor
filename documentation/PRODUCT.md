# 产品说明：SiliconScope 半导体产业情报台

版本 2.0 · 2026-11-11 · 维护者：SiliconScope contributors

## 1. 一句话定位

**用一套公开、可核查的口径，把全球半导体产业链的结构、公司位置、周期状态与基础知识放进同一张桌面。**

它不是行情终端，也不是选股工具。它是一个**研究台**：帮助读者在 10–30 分钟内建立对一个环节或一家公司的结构感，并清楚知道自己依据的数据有多完整。

## 2. 为什么做

半导体同时具备三个特征，使它难以被单一工具服务：

1. **知识门槛高**：设备、材料、制程、封装、存储各有术语体系，跨市场沟通容易失真。
2. **强周期**：同一个指标在周期顶部和底部的含义相反，静态估值经常误导。
3. **地缘属性强**：出口管制、补贴与产能本地化会快速改变公司收入结构。

现有的免费信息要么是碎片化新闻，要么是只覆盖单一市场的行情页。读者需要的是一个**结构化的中间层**：不预测价格，但把“这个环节怎么赚钱、谁在里面、现在是什么状态、数据是否可信”讲清楚。

## 3. 目标用户与使用场景

| 用户 | 典型任务（JTBD） | 本站提供 |
| --- | --- | --- |
| 学习产业链的学生 / 研究者 | “我想在面试或写报告前，快速搞懂设备、材料、代工、封测的关系” | 产业链页 + 9 篇知识长文 + 三语术语表 |
| 需要全局视角的分析师 / 从业者 | “给我一张表，能按环节和地区看全球主要玩家与估值” | 公司图谱 + 环节统计 + 估值-质量散点 |
| 关注公开数据口径的个人投资者 | “这个分数怎么来的？数据缺了多少？” | 方法页 + 数据完整度 + 快照时间与来源 |

**明确不服务的场景**：日内交易、杠杆与仓位建议、目标价、财报预测、新闻全文阅读。

## 4. 范围

### 覆盖

- 8 个环节：EDA/IP、设计、晶圆制造、存储、设备、材料、封装测试、模组。
- 11 个总部地区：中国大陆、香港、台湾、美国、日本、韩国、荷兰、德国、法国、瑞士、英国（按总部）。
- 124 家上市公司，每家一个主上市地，避免重复计算。
- 三语：简体中文（默认）、English、日本語。

### 不覆盖

- 未上市公司（如长江存储、SMIC 部分子公司）。
- 纯终端品牌与分销商，除非其收入主要来自半导体。
- 分钟级行情、盘口、期权与衍生品。
- 个股新闻聚合之外的深度报道。
- 任何形式的投资建议。

## 5. 信息架构

```text
/                       中文首页（市场状态 + 结构 + 清单）
/companies.html         公司图谱（筛选 / 排序）
/companies/{id}.html    公司页
/value-chain.html       产业链全景
/knowledge.html         知识库索引
/knowledge/{slug}.html  知识长文
/glossary.html          术语表
/methodology.html       方法与边界
/about.html             目的、来源、许可、构建信息
/en/... /ja/...         英文与日文镜像（结构完全一致）
/api/snapshot.{lang}.json   本地化数据快照
/latest_data.json       旧版兼容 payload（iOS）
```

四层内容结构：

1. **事实层**：行情、估值、市值、52 周区间、数据时点与来源。
2. **结构层**：环节、角色、地区、市值分布、集中度。
3. **判断层**：研究优先级、风险标签、市场状态、研究清单。
4. **方法层**：因子定义、权重、阈值、局限与免责声明。

判断层永远可以追溯到事实层与方法层；方法层永远公开。

## 6. 核心产品逻辑

### 6.1 先分类，再比较

不同环节的毛利率、资本强度、周期驱动完全不同，跨环节直接比 PE 没有意义。因此：

- 所有因子在**同环节内**做百分位归一化；
- 环节样本少于 8 家时退回全样本，并在方法页说明；
- 页面同时展示绝对数值与相对分数，避免“分数即结论”。

### 6.2 分数只排序，不预测

“研究优先级”回答的是“先读哪家公司”，不是“买哪家公司”。

- 分数高 = 在当前公开数据下，质量、估值、动能、规模的综合位置更靠前；
- 分数低 ≠ 公司差，可能只是估值高、数据缺失或处于周期底部；
- 页面不出现“买入 / 卖出 / 目标价 / 仓位”。

### 6.3 完整性是一等公民

每条记录都有数据完整度（8 个字段的覆盖比例），每个页面都显示数据时点与来源。缺失字段显示 `—`，不猜测、不补零。抓取失败时使用上一份快照，并在页面标记过期。

### 6.4 三语对等

三种语言的页面结构、数据与图表完全一致，只有文案与内容语言不同。任何语言缺内容，CI 失败。这样避免“英文站是精简版”的常见问题。

## 7. 设计原则

1. **Source of truth 唯一**：公司主数据只在 `data/universe.csv`，分类标签只在 `data/taxonomy.json`。
2. **构建期完成一切**：不在浏览器里请求第三方 API，不用 CDN，图表为 SVG。
3. **可核查**：每个数字都能追溯到快照文件与字段定义。
4. **克制的视觉**：信息密度优先，颜色只用于表达涨跌与分类，不做装饰性动画。
5. **可打印、可访问**：语义化表格、键盘可达、对比度满足 WCAG AA、支持 `prefers-reduced-motion`。
6. **可持续**：无服务器、无数据库、无付费 API；月度维护成本接近零。

| 使用深度 | 公司页 / 知识页访问比 | 监测趋势，不设硬目标 |

## 9. 风险与合规

- **数据延迟**：行情为延时或收盘价，页面明确标注，不用于交易决策。
- **数据错误**：提供来源与快照，接受纠错；不承诺绝对准确。
- **版权**：新闻只保留标题、来源、日期与链接；知识内容为原创解释并附参考来源。
- **投资建议风险**：全站反复声明“研究目的、不构成投资建议”，方法页单列免责声明。
- **供应商依赖**：单一行情源，但有快照兜底与符号映射审计；后续可扩展多源。

## 10. 版本与演进

- 语义化版本：主版本用于信息架构或方法变更，次版本用于功能与覆盖扩展，补丁用于数据修正。
- 方法变更必须更新 `documentation/METHODOLOGY.md`、站内方法页与 `CHANGELOG.md`，并在 PR 中说明影响。
- 详见 [ROADMAP.md](ROADMAP.md) 与 [OPERATIONS.md](OPERATIONS.md)。
